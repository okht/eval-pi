## Pi 与模型模块

安装版本为 `@earendil-works/pi-coding-agent@1.0.0` 和 `@earendil-works/pi-ai@1.0.0`。本地读取 SDK 实现，确认其提供 OpenAI「Sign in with ChatGPT」OAuth。

已验证的实现边界：

- 默认模型从 SDK 实际目录选择，本轮目录包含 `gpt-6.1-sol`；模型能否使用仍取决于登录账号的实际授权。
- 主 Agent 的真实 SDK 会话初始化成功，启用工具只有 `submit_plan`，会话不写入 SDK 历史文件；该初始化检查拦截了推理调用。
- 主 Agent 无默认文件读写、Shell 工具、技能或扩展发现，只接收应用提供的项目摘要、当前方案及限量保存执行证据。提交工具只能产生草案。
- 每次 Judge 调用使用新消息上下文、新 session ID，无工具，并设置 `cacheRetention: none`。用替身检查第二个 Case 的输入中没有第一个 Case 的内容。
- Judge 严格接收 `pass`、`fail`、`pending` 与理由；无效 JSON、未知判定或缺少理由会报错，不会自动算作通过。
- API Key 仅保存在运行时内存，不写入模型选择配置。OAuth 使用本应用独立的凭据目录；没有读取或复制已有 Codex、Pi 的登录凭据。
- 内置 OpenAI provider 的订阅认证不能被自定义地址重定向。自定义服务必须选择 `openai-compatible` 并提供自己的 API Key。
- 登录只在用户显式触发后启动。已用替身验证登录完成、取消、手动回调和脱敏错误；本轮真实授权由用户完成，应用已收到成功回调并完成实际推理。
- 方案执行边界统一为 1–50 个 Case、每个重复 1–10 次、每批最多 300 次、目标单次超时 100–180000 毫秒，默认仍为 5000 毫秒。目标超时包含其内部模型调用与工具交接；规划、评分、HTTP 和 PDF 保留各自超时。
